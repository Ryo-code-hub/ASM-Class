# 作业五 思路说明：递归调用

## 一、题目要求

求斐波那契数列第 n 项，F(0) = 0、F(1) = 1、F(n) = F(n-1) + F(n-2)。键盘输入 n（1 ≤ n ≤ 100），输出 F(n)。要求以递归实现，过程中使用寄存器，合理设定栈空间并说明其容量依据，另用 C 语言实现并察看反汇编。

## 二、关键判断：数据规模决定表示方法

本题最容易被忽略的一点是结果的量级。F(100) = 354224848179261915075，共 21 位十进制、69 个二进制位。各宽度的表示能力如下：

| 表示宽度 | 可算到的最大 n |
|---|---|
| 16 位无符号 | 24 |
| 32 位无符号 | 47 |
| 64 位无符号 | 93 |
| **5 个字（80 位）** | **116** |

因此无论汇编还是 C，都不能用单个寄存器或单个整型变量存放结果，必须采用多精度表示。本程序把一个大数表示成 **5 个 16 位字（共 80 位）**，低位字在前，足以覆盖 n ≤ 100。

## 三、递归形式的选择

若直接照递推式写成双重递归 `Fib(n) = Fib(n-1) + Fib(n-2)`，调用次数按 2 的 n 次方增长，n = 100 时在有限时间内无法完成。

因此改用"返回相邻两项"的线性递归：

```
FIB2(n)  返回 ( F(n), F(n+1) )
    若 n = 0 ：返回 ( 0, 1 )
    若 n > 0 ：先求 (a, b) = FIB2(n-1)，再返回 ( b, a+b )
```

由于 a = F(n-1)、b = F(n)，故 b = F(n)、a+b = F(n+1)，与递推式完全一致。该形式每层只产生一次递归调用，递归深度恰为 n，计算量为 O(n)，既满足"用递归实现"的要求，又能在 n = 100 时正常完成。

参数通过寄存器传递：`CX` 存放 n，`BX` 存放目标缓冲区地址；缓冲区需容纳两个大数（20 字节）。

## 四、多精度运算的三个基本操作

整个程序只用到三种大数运算，均按 16 位字逐个处理：

1. **复制**（`BCOPY`）：把 5 个字从源地址搬到目标地址。
2. **带进位加法**（`BADD`）：用 `ADC` 指令实现。要点是**进位标志必须连续传递**，故指针只能以 `INC` 递增（INC 不改变 CF），循环用 `LOOP`（同样不改变 CF），由 `ADC` 把上一位的进位带入下一位。
3. **除以 10**（`BDIV10`）：从最高位字开始逐字做 `DIV`，前一次的余数作为下一次的高位继续除，最后一次的余数即整数的个位。反复执行即可逐位取出十进制各位数字，配合栈的倒序输出，实现十进制打印。

乘法并未使用：本程序求的是斐波那契数列，只涉及加法。

## 五、栈空间分析与实测

递归的栈开销可按帧精确计算。`FIB2` 每层的栈帧由三部分构成：

| 组成 | 字节数 |
|---|---|
| 返回地址 | 2 |
| 保存的 6 个寄存器（AX、BX、CX、DX、SI、DI） | 12 |
| 局部区（接收子调用结果的两个大数） | 20 |
| **合计** | **34** |

递归深度为 n+1 层（FIB2(n) 到 FIB2(0)），故 n = 100 时峰值为 101 × 34 = **3434 字节**。

为验证该推算，另写了一个插桩版本（`FIBSTK.ASM`），在每层入口记录栈指针的最低值，程序结束时输出峰值用量。实测结果与推算完全吻合：

| n | 递归层数 | 实测峰值（字节） | 计算值 34 × 层数 |
|---|---|---|---|
| 1 | 2 | 68 | 68 |
| 10 | 11 | 374 | 374 |
| 100 | 101 | **3434** | 3434 |

据此把栈设为 `.STACK 2000H`，即 8192 字节。相对 n = 100 所需的 3434 字节约有余量 2.4 倍；按每层 34 字节折算，理论上可支撑约 240 层递归，即 n 接近 239（此时受限的已是 80 位表示，而非栈空间）。

关于单步跟踪：平台的 DOSBox 中未提供 `DEBUG.EXE`，无法逐条单步观察栈指针变化。上述插桩测量是对该要求的等效实现——它直接给出了每一次调用、返回过程中栈指针的极值。

## 六、C 语言实现与反汇编

C 版本采用与汇编完全对应的算法，同样以 5 个 `unsigned short` 表示一个大数。运行输出与汇编版本一致。

反汇编显示，递归函数 `fib2` 的要点如下：

- 局部数组 x、y 由 `sub esp,1Ch` 在栈上开出，每层各有一份，与汇编版本 `SUB SP, 2*BNSIZE` 的做法一致；
- 递归调用即一条 `call _fib2`，每层栈帧 36 字节（4 + 4 + 28），与汇编的 34 字节数量级相同；
- 参数按 cdecl 约定从右往左压栈，函数体内由 `[ebp+8]`、`[ebp+0Ch]`、`[ebp+10h]` 取得；
- MSVC 额外插入了 `/GS` 栈保护（入口保存 cookie、出口校验），这是 16 位 Turbo C 所没有的编译器附加开销；
- 开启优化后，栈帧取消、数组清零与拷贝改用 SIMD 指令成批处理，但 `call _fib2` 依然保留——递归结构无法被优化器消除。

完整的逐条注释见同目录 `DISASM.TXT`。

| 输入 n | 输出 |
|---|---|
| 1 | F(1) = 1 |
| 10 | F(10) = 55 |
| 24 | F(24) = 46368 |
| 47 | F(47) = 2971215073 |

## 八、文件与运行

| 文件 | 说明 |
|---|---|
| `FIB.ASM` | 汇编实现（递归 + 多精度 + 栈空间设定） |
| `FIB.C` | 第 7) 小问：C 语言实现 |

在平台的 DOS 环境中编译与运行：

```dos
BUILDD FIB        :: 汇编并链接，产物生成于 BUILD\ 子目录
BUILD\FIB         :: 运行，按提示输入 n
```
