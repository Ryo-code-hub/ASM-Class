# 作业六 思路说明：输出日历

## 一、题目要求

输入年份（1900~2099）与月份（1~12），输出对应月历。除正确性外还要求：功能封装为过程；尝试寄存器、数据段、栈三种参数传递方式并比较；用至少两个代码段封装程序；注意条件跳转的步长限制；体会短跳转、近跳转与远跳转的区别；另用 C 语言实现并察看反汇编。

## 二、程序结构

程序分四个段，其中两个是代码段：

| 段名 | 类别 | 内容 |
|---|---|---|
| `STACKS` | `'STACK'` | 栈空间，2048 字节 |
| `DATAS` | `'DATA'` | 变量、月名表、天数表、星期修正表 |
| `CODES` | `'CODE'` | 第一代码段：输入、校验、输出、月历排版 |
| `CALC` | `'CALC'` | 第二代码段：纯计算，不涉及输入输出 |

`CODES` 调用 `CALC` 中的过程一律用远调用，`CALC` 内部的调用用近调用。第二段只放纯计算过程，不接触 DS，因此不存在数据段切换问题。

主要过程：

| 过程 | 所在段 | 参数传递 | 说明 |
|---|---|---|---|
| `GET_DAYS` | `CALC` | 寄存器 | `AX`=年、`BX`=月 → `AX`=天数 |
| `IS_LEAP` | `CALC` | 寄存器 | `AX`=年 → `AL`=1 闰年/0 平年 |
| `GET_DOW` | `CALC` | 栈 | 压入年、月、日 → `AX`=星期 |
| `SHOW_GRID` | `CODES` | 数据段 | 读 `LEAD`、`DAYS` 排布月历 |
| `PRINT_NUM` | `CODES` | 数据段 | 读 `OUTVAL` 输出两位十进制 |
| `PARSE_NUM` | `CODES` | 数据段 + 寄存器 | 把输入的数字串转成数值 |

## 三、三种参数传递方式及其比较

**1. 寄存器传参（`GET_DAYS`）**

调用前把年和月分别放入 `AX`、`BX`，过程直接使用。

优点是速度最快，不占用内存、不改变栈结构，指令也最省。缺点是可传的参数个数受寄存器数量限制，而且寄存器会被过程占用，调用者需要事先保存关心寄存器的值。本题 `GET_DAYS` 内部保护了 `BX`、`CX`、`DX`、`SI`，只把结果留在 `AX` 中。

**2. 数据段传参（`PRINT_NUM`）**

调用者先把待输出的数写入变量 `OUTVAL`，过程从数据段读取。

优点是参数个数几乎不受限制，很适合放数组、字符串这类大数据；缺点是要占用全局存储，过程不再是"纯"的（有副作用、不可重入），而且每次取参都要访问一次内存。

**3. 栈传参（`GET_DOW`）**

调用者依次压入年、月、日，过程中通过 `BP` 访问；过程末尾用 `RET 6` 返回，顺带把三个参数弹出。

优点是支持任意多个参数、天然可重入，且与递归、嵌套调用相容最好；缺点是每次压参、取参都要读写内存，速度最慢，而且栈的布局必须与参数顺序严格对应——一旦把偏移算错，程序不会报错，只会算错结果。

本程序在编写 `GET_DOW` 时就踩过这个坑：调用者先压年、后压日，因此最后压入的"日"离栈顶最近，`[BP+6]` 对应的是**日**而非年。最初把 `[BP+6]` 当作年份使用，2026 年 11 月被算成 1 号是星期六（正确应为星期日），把 `[BP+6]` 与 `[BP+10]` 对调后结果才正确。栈传参的错误往往不报错、只算错，这是它最主要的代价。

## 四、段间调用的处理细节

远调用与近调用的差别就在编码上。本程序的 `.LST` 中可以看到两种调用并存：

```
     169 0079  9A 0000 ---- R          CALL  FAR PTR GET_DAYS     ; 远调用，5 字节
     177 008D  9A 005E ---- R          CALL  FAR PTR GET_DOW      ; 远调用，5 字节
     207 00B3  E8 0196 R               CALL  PUTCH                ; 近调用，3 字节
     221 00D7  E8 019D R               CALL  NEWLINE              ; 近调用，3 字节
```

- 近调用 `E8` 后面只跟 16 位偏移，段基址不变，故栈上只压 2 字节返回地址；
- 远调用 `9A` 后面同时跟 16 位偏移和 16 位段值，栈上要压 4 字节（先压 `CS`、再压 `IP`），返回时两个都要弹出。

由于 `CALC` 是独立段而不是 `CODES` 的延续，MASM 生成了带段重定位的 `9A`；若两段被合并成一段，同样的调用会被编译成 3 字节的 `E8`。

这里还有一个必须注意的语法细节：**对后向定义（调用点在前、过程定义在后）的远过程，`CALL` 必须写成 `CALL FAR PTR 过程名`**。否则 MASM 5.0 会报

```
calendar.asm(130): error A2071: Forward needs override or FAR
```

加上 `FAR PTR` 覆盖后才通过。

## 五、条件跳转的步长限制

`Jcc` 指令的位移只有 1 个字节，可取 -128~+127。若目标超出该范围，**MASM 5.0 不会自动改写，而是直接报错**。用专门的验证程序 `JUMPDEMO.ASM` 实测：

```
jumpdemo.asm(16): error A2053: Jump out of range by 73 byte(s)
```

正确的处理办法是手工把"条件跳转"改写成"条件取反的短跳转 + 一条近跳转"：

```asm
        JE   FAR_TARGET          ; 超范围，报 A2053
; 改为
        JNE  SKIP                ; 条件取反，跳过下面这条
        JMP  FAR_TARGET          ; 近跳转位移 16 位，±32767 足够
SKIP:
```

改写后的编码为：

```
      35 0006  75 03              JNE     SKIP          ; 2 字节，跳过 3 字节
      36 0008  E9 00D3 R          JMP     FAR_TARGET    ; 3 字节，近跳转
```

即用 5 字节换来了足够的跳转范围。本程序的 `SHOW_GRID` 循环体虽不短，但测得的位移都在范围之内（例如 `JBE GRID_NEXT` 的位移为 `CA`，即 -54），所以全部落在短跳转内；这也说明位移的正负号要按补码理解，`CA` 是 -54 而不是 202。

## 六、短跳转、近跳转与远跳转

| 类型 | 编码 | 长度 | 位移范围 | 本程序中的例子 |
|---|---|---|---|---|
| 短条件跳转 | `Jcc` + 1 字节位移 | 2 | -128~+127 | `74 05`(JE)、`75 0B`(JNE)、`72 05`(JB)、`76 CA`(JBE) |
| 短无条件跳转 | `EB` + 1 字节位移 | 2 | -128~+127 | `EB 8F`（见 C 反汇编）、`EB 0C` |
| 近跳转 | `E9` + 2 字节位移 | 3 | -32768~+32767 | `E9 00D3`（`JUMPDEMO` 中） |
| 近调用 | `E8` + 2 字节偏移 | 3 | 段内 | `E8 0196`(CALL PUTCH) |
| 远调用 | `9A` + 2 字节偏移 + 2 字节段值 | 5 | 段间 | `9A 0000`(CALL GET_DAYS) |
| 近返回 | `C3` / `C2` + 2 字节 | 1 / 3 | 段内 | `C3`（SHOW_GRID 的 RET） |
| 远返回 | `CB` / `CA` + 2 字节 | 1 / 4 | 段间 | `CA 0006`（GET_DOW 的 RET 6） |

对照可见：

- **短跳转与近跳转**只差在位移宽度（8 位与 16 位），IP 相对跳转这一点相同，因此都属于**段内**跳转；
- **远跳转/远调用**同时改写 `CS` 与 `IP`，属于**段间**跳转，指令因此多出 2 字节的段值；
- 返回地址占用的栈空间也随之不同：近调用压 2 字节，远调用压 4 字节。`GET_DOW` 中 `[BP+4]` 才是返回的 `CS`，参数从 `[BP+6]` 才开始，正是这个差别造成的。

另外在 `SHOW_GRID` 中可以看到 `EB 0C 90`：这是一条 2 字节的短跳转加一个 `90`（NOP）。MASM 在首次扫描时按 3 字节预留了位置，最终距离够短，便用 NOP 把多出的 1 字节填平——这也从侧面说明汇编器对跳转长度的处理是分两遍完成的。

## 七、C 语言实现与反汇编

C 版本用同样的算法实现，输出与汇编版本逐字符相同。反汇编中值得注意的几点：

- `y / 4` 被优化成 `sar ecx,2`，前面还有 `cdq`、`and edx,3`、`add eax,edx` 三条指令做符号补偿，以保证有符号除法"向零取整"的语义；
- `y / 100`、`y / 400` 与 `% 7` 不是 2 的幂，只能用 `idiv`；
- `show_grid` 的一个 `for` 循环在机器级被拆成初始化、条件、循环体、步进四块，且顺序与书写顺序不同：初始化后直接跳到条件，步进块排在条件块之前；
- 未优化时局部变量都在栈上，循环回跳是一条 2 字节的短跳转 `EB 8F`（位移 -113）；
- 32 位平坦模型中所有代码同段，编译器只生成近调用，不会出现 `9A` 这样的远调用。

逐条注释见同目录 `DISASM.TXT`。

## 八、实测结果

| 输入 | 结果 |
|---|---|
| 2026-11 | 与题目示例逐字符一致 |
| 2026-09 | 1 号在 Tu 列，首行前置 2 个空格 |
| 2026-02 / 2000-02 / 2024-02 | 分别按平年 28 天、闰年 29 天正确输出 |
| 1900-01 | 1900 年不是闰年（能被 100 整除但不能被 400 整除），处理正确 |
| 2099-12 | 年份上界，正确 |
| 1899、2026-13 | 输出对应的错误提示并退出 |

汇编 0 Warning / 0 Severe Errors；C 版本对 2026 年 11 月的输出与汇编版本相同。

说明：以重定向方式测试时，输入行末没有控制台回显，因而题目示例中月份输入后的那个空行不会出现；交互运行时该空行由 `NEWLINE` 输出，与示例一致。
